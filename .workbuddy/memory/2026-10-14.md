# M7：批量「每张图独立参数」

用户下达 `实现批量流水线的"每张图独立参数"`。AskUserQuestion 确认 3 条（**均采纳推荐**）：
粒度 = 完整流水线副本；入口 = 面板顶部切换编辑对象；范围 = 只做处理参数（输出仍整批统一）。
自检 **346 → 358 项全绿**。

## 设计
- `BatchItemViewModel.Steps`（`null` = 跟随公共设置）+ `HasCustomSteps` / `ParameterScopeText`
- 面板的 `_batchSteps` 改成**转发属性**（有自定义就返回那张图的列表）
  ⇒ 二十多处参数编辑代码一行未改，而"切换编辑对象 = 换一整套参数"自动成立
- 三个命令：为这张图单独设置 / 恢复为公共设置 / 把这张图的参数应用到公共设置
- 队列里标「自定义」；参数面板顶部写明"正在编辑谁"

## ⚠️ 踩到一个真 bug（自检抓出来的）
`_batchSteps` 做成转发属性之后，`SnapshotBatchSteps()` 里的 `_batchSteps` **不再是公共列表**。
结果是：选中某张自定义图之后，**其余所有图都跟着用了那张图的参数**，界面上完全看不出来。
修法：拆成语义明确的 `SnapshotSharedSteps()`（执行用）与 `SnapshotActiveSteps()`（仅界面摘要用）。
**教训**：转发属性会悄悄改掉"这个字段到底指谁"的语义，凡是"快照/执行"路径都必须显式点名
`_sharedXxx`，不能图省事复用转发属性。这与标签页那次是同一个手法的同一类风险。

## 自检设计（关键：断言输出像素而不是对象引用）
- 隔离性：改 A 的自定义参数 ⇒ 公共与 B 都不变；改公共 ⇒ 已脱离的 A 不变、跟随的 B 跟着变
- 深拷贝：`ReferenceEquals` 断言（注意要先抓住公共那一步的引用 ——
  选中 A 之后 `BatchSteps` 就指向 A 的列表了，拿它比等于同义反复）
- **端到端**：真跑一遍批量，用**输出文件里的水印象限像素数**证明各按各的跑
  （A 左上 1528px / 右下 0px；B 左上 0px / 右下 2597px）。
  这条比对象引用强得多 —— "状态串味"这类错误跑不掉。
- 删掉正在编辑的图 → 不崩、面板切回公共、公共流水线不受影响

## 测试自己的两个坑
1. `BatchSteps` 是转发属性，选中 A 时返回的是 A 的列表 ⇒ 深拷贝断言变成同义反复。
2. B 跟随公共设置时 `Steps == null` ⇒ `itemB.Steps[0]` 必然空引用。
   （真正的断言对象应当是公共那一步本身。）
