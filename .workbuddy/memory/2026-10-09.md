### 关键结论
- **检测必须做两层**：本项目无 App.config，exe 声明 CLR v4.0，所以在只装 4.5/4.6.2 的 Win7 上
  **exe 能起来**、却在用 4.8 API 时半路崩。程序内检测管"起来了但版本不够"，启动器 bat 管"根本起不来"。
- **两套 4.8 判定**：启动器匹配 `Version` 字符串前缀（`findstr /c:"4.8."`），程序读 `Release >= 528040`。
  自检跨实现校验两者结论一致。
- **文件关联根键做成构造参数**，自检写进 `Software\PSText-SelfTest-<guid>`，绝不碰用户真实关联。
- **本机自检里关联写入流程是 Skip 的**：本机工具层拦下可执行文件写注册表。
  已核实不是代码问题（Python winreg 三种视图都能建同样的键；换名字/目录/通道/绕沙箱都一样）。
  自检改为先探测 HKCU 可写性，不可写就明确 Skip 并保留纯逻辑断言，避免 `--selftest` 恒红。

### 踩坑（新增，已记 README §6）
- **传统 csproj 不消费 `AssemblyTitle`/`AssemblyVersion`** → exe 版本恒为 0.0.0.0，必须写 `Properties/AssemblyInfo.cs`。
- **`reg query` 把 REG_DWORD 打印成十六进制**（`0x82309`）→ 不能用 Release 做数值比较。
- **`Environment.Version` 永远报 4.0.30319**（它是 CLR 版本）→ 判框架版本必须读注册表。
- **32 位进程读 `HKLM\SOFTWARE` 会被重定向到 Wow6432Node** → 两个注册表视图都要读，取较大值。
- **Python 3.13 的 `ZipFile.writestr` 会强制置 UTF-8 标志位**（`zinfo.flag_bits = _MASK_UTF_FILENAME`），
  只覆盖 `_encodeFilenameFlags` 不够 → 必须 `& ~0x800`。打包自检第一次跑就抓出了我自己补丁的这个 bug。
- **中文 `.ps1` 必须带 BOM**（PS 5.1 否则按 ANSI 解析）；脚本被程序调用时用 `Write-Output` 而非 `Write-Host`
  （后者走信息流，`2>&1` 抓不到）。
- **执行策略会拦别人写的 `.ps1`** → `Set-ExecutionPolicy -Scope Process Bypass`。
- sandbox 的 safe-delete 垫片会拦 `Remove-Item -Recurse` → 改用 `[System.IO.Directory]::Delete`。
- **WinExe 没有控制台** → `AttachConsole(ATTACH_PARENT_PROCESS)`，失败退回弹窗。

## 第一轮：马赛克/模糊 + 八向手柄 + 右键菜单（自检 258 → 299）

### 遮盖标注
- `Services/Filters/MosaicFilter.cs`：区域块平均 + 带外扩的区域内高斯模糊，**纯函数**
- `Services/Filters/MosaicSourceProvider.cs`：**拉取式**素材提供（构造时传取像素的委托，
  每次现取现用 ⇒ **不需要任何失效通知**，从根上避免"底图换了忘了失效"）
- `AnnotationVisualBuilder` 把素材做成 ImageBrush 当 `Fill` 用 ⇒ **渲染器一行未改**
- 三个关键决定：
  1. 不做整幅预处理缓存（12MP 是 48MB；按区域生成是几十 KB、亚毫秒，可逐帧重算）
  2. **块网格锚定图像坐标 (0,0)**，区域先向外对齐到块边界——否则拖动时马赛克会"流动"
  3. 叠加层与合并**共用同一个 provider 实例**（与共用几何同理），否则所见非所得

### 八向缩放手柄
- `Models/AnnotationResize.cs`：纯函数缩放计算（方向 / 不许翻转 / 最小尺寸 / 宽高比 / 中心基准）
- 手柄尺寸按「屏幕像素 ÷ 缩放」折算（100% 是 11px，200% 是 5.5px）
- **手柄命中必须优先于"拖动标注"**，否则永远改不了尺寸
- 文字标注用"与字号成比例的虚拟盒" ⇒ 拖角 = 改字号
- 箭头缩放记录原始 X1>X2 / Y1>Y2 再回填 ⇒ **不会掉头**
- 光标名由 VM 出、XAML 转换器落地 ⇒ code-behind 仍不设置外观

### 右键菜单
- `SystemFileAssociations\image\shell` 下两个动词（一处覆盖所有图片类型）
- 用 `MUIVerb` 写显示名；**不写 `Extended`**（否则要按 Shift 才出现）
- 新增 `--print`：**只到打印预览**，刻意不做静默打印（Windows 自己的打印动词也是弹向导的）

### 顺手修掉的缺陷（自检抓出来的）
`VisualBounds` 原来统一按 `max(线宽, 字号*0.6)+4` 外扩，而 `FontSize` 对所有标注都有默认值 28
⇒ 一个 4px 粗的矩形也带 20 多像素抓取边距，在它旁边点一下会被判成"选中并拖动"而不是"新建标注"。
现改为**按类型取**（细矩形 6px / 文字 20.8px / 箭头 16px / 遮盖 0）。
发现过程：`[35]` 想在空白处点一下新建文字，结果挪动了箭头。

### 自检里的两处"我的测试写错了"
- 用 `CreateHorizontalRamp` 比对时用了**红**通道，而那图的渐变在**蓝**通道、红恒为 128
  ⇒ 那条"块值等于平均值"的断言其实在比常量、等于空转。改用蓝通道后才真正生效。
- 符号写反（`VisualBounds.Left - Left` vs `Left - VisualBounds.Left`）。

## 第二轮：多文档标签页（自检 299 → 311）

### 改造思路（这次能做得稳的关键）
`MainViewModel` 把"当前文档"的状态平铺成实例字段，共 **374 处引用**。逐个改调用点风险太高，
于是把**私有字段换成"转发到当前会话"的私有属性**：

```csharp
private ImageDocument _document
{
    get { return _activeSession.Document; }
    set { _activeSession.Document = value; OnDocumentReplaced(); }
}
```
⇒ **374 处调用点一行未改**，而"切换标签 = 换一整套状态"自动成立。

验证方式：改完先跑原有 299 项断言（覆盖加载/编辑/撤销/标注/几何/打印的完整生命周期），
**全绿才继续加新功能**。

### 两条不变量
1. **至少一个标签**：关掉最后一个时把它**重置为空会话**而不是移除
   ⇒ `ActiveSession` 永不为 null ⇒ 转发属性一律不用判空
2. **切换标签必须整体刷新**（`RefreshAfterSessionChange` 故意写得啰嗦）：
   撤销步数 / 调整滑块 / 标注列表 / 缩放比例**都属于某个文档**，少刷一个就会看到上一个文档的值

### 关键改动点
- `ViewModels/DocumentSession.cs`：每文档工作台（历史 / 标注 / 调整 / 缓存 / 视图 + 标签标题）
- `ViewModels/MainViewModel.Tabs.cs`：会话生命周期、`ActivateSession`、打开/关闭
- `LoadFromPathAsync`：**空标签复用、已有文档则开新标签**（不顶掉正在编辑的那张）；
  加载失败时把刚建的空标签撤掉
- `ConfirmCloseAsync` 改为**遍历所有标签**（只看当前标签会把别的标签的修改悄悄丢掉）
- `MainWindow.OnClosing` 改用 `HasAnyUnsavedChanges`
- 标签栏是**独立整行**（横跨窗口宽度，不被 296px 的右侧面板挤窄）
- 新增 Ctrl+W 关闭当前标签
