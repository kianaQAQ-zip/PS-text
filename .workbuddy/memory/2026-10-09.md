### 关键结论
- **检测必须做两层**：本项目无 App.config，exe 声明 CLR v4.0，所以在只装 4.5/4.6.2 的 Win7 上
  **exe 能起来**、却在用 4.8 API 时半路崩。程序内检测管"起来了但版本不够"，启动器 bat 管"根本起不来"。
- **两套 4.8 判定**：启动器匹配 `Version` 字符串前缀（`findstr /c:"4.8."`），程序读 `Release >= 528040`。
  自检跨实现校验两者结论一致。
- **文件关联根键做成构造参数**，自检写进 `Software\PSText-SelfTest-<guid>`，绝不碰用户真实关联。
- **本机自检里关联写入流程是 Skip 的**：本机工具层拦下可执行文件写注册表。
  已核实不是代码问题（Python winreg 三种视图都能建同样的键；换名字/目录/通道/绕沙箱都一样）。
  自检改为先探测 HKCU 可写性，不可写就明确 Skip 并保留纯逻辑断言，避免 `--selftest` 恒红。

### 踩坑（新增，已记 README §6）
- **传统 csproj 不消费 `AssemblyTitle`/`AssemblyVersion`** → exe 版本恒为 0.0.0.0，必须写 `Properties/AssemblyInfo.cs`。
- **`reg query` 把 REG_DWORD 打印成十六进制**（`0x82309`）→ 不能用 Release 做数值比较。
- **`Environment.Version` 永远报 4.0.30319**（它是 CLR 版本）→ 判框架版本必须读注册表。
- **32 位进程读 `HKLM\SOFTWARE` 会被重定向到 Wow6432Node** → 两个注册表视图都要读，取较大值。
- **Python 3.13 的 `ZipFile.writestr` 会强制置 UTF-8 标志位**（`zinfo.flag_bits = _MASK_UTF_FILENAME`），
  只覆盖 `_encodeFilenameFlags` 不够 → 必须 `& ~0x800`。打包自检第一次跑就抓出了我自己补丁的这个 bug。
- **中文 `.ps1` 必须带 BOM**（PS 5.1 否则按 ANSI 解析）；脚本被程序调用时用 `Write-Output` 而非 `Write-Host`
  （后者走信息流，`2>&1` 抓不到）。
- **执行策略会拦别人写的 `.ps1`** → `Set-ExecutionPolicy -Scope Process Bypass`。
- sandbox 的 safe-delete 垫片会拦 `Remove-Item -Recurse` → 改用 `[System.IO.Directory]::Delete`。
- **WinExe 没有控制台** → `AttachConsole(ATTACH_PARENT_PROCESS)`，失败退回弹窗。
