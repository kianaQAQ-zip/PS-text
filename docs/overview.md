## 你要的"能选中再改参数"，是这样成立的

标注不是"画上去的像素"，而是**对象**：画面 = 底图 + 全部对象实时渲染，底图像素一动不动。

所以"把那个箭头改成蓝色"只改对象列表里的一个属性，然后重绘这一个对象——底图完全不用碰。这正是像素方案做不到的地方：一旦画死，除了重画没有别的办法。

自检里有一条断言直接打在这上面：**点击已有标注即选中，且不会误创建新对象**；接着改颜色，**立即生效**。

## 自动合并：一步独立的历史

你选的「破坏性操作前自动合并」是这么落地的：

```
底图 + 标注叠加层  ──(执行反色/裁剪/缩小…)──►  先合并，再执行
```

历史里因此是**两步**：「合并标注 → 反色」。所以撤销两次才回到"标注可编辑 + 未反色"。我把这个行为写进了自检断言（**两次撤销逐步回退**），而不是含糊过去——因为"撤销一次发现标注没回来"是用户会立刻察觉的事。

顺带说一个必须处理的坑：**合并命令要同时还原像素和对象列表**。只还原像素 → 撤销后标注凭空消失（列表还是空的）；只还原列表 → 画面上出现两份标注（像素里一份 + 叠加层一份）。这两条都会让人怀疑软件坏了。

## 三个实现细节

**叠加层与合并共用同一份几何。** 如果预览和最终合并各画各的，用户看到的就是假的——这类"所见非所得"最难查。所以两边都走 `AnnotationVisualBuilder`。

**箭头是一个填充多边形**（箭杆细长四边形 + 箭头三角形），不是"一条线 + 一个三角"。这样叠加层和合并渲染都只需一次绘制调用，线宽变化时箭杆与箭头也不会裂开一道缝。

**导出和打印不破坏标注层。** 保存时把标注烘进**副本**再写文件，打印预览与打印同样用副本。所以你存完盘还能回头改那个箭头的颜色——而不是"一保存就变成死图了"。

高亮做成了 35% 半透明混合，自检断言结果像素是 **210/156/156** 这种"既不是底色也不是标记色"的中间值——实色覆盖会得到 226/75/74，一眼能分辨。

## 没做的部分（说清楚，不假装完整）

- **马赛克 / 模糊遮盖**没做。它和其它标注不一样：需要在叠加层里显示"像素化的底图"，得额外缓存一份小图，比矢量标注多一层。我把它单列为后续项，而不是塞一个"预览和结果不一致"的假实现进来。
- **选中后只能拖动挪位，没有八向缩放手柄**。改尺寸的方式是删掉重画。要补的话不难，但会显著增加交互代码量。

## 现在的撤销架构（三种模型并存）

| 模型 | 用在哪 | 代价 |
|---|---|---|
| 整幅压缩快照 | 滤镜 / 裁剪 / 缩放 / 旋转 | 12MP 约 17 MB/步 |
| 区域历史（包围盒前后像素） | 仿制图章 | 一笔 200×200 仅 160 KB |
| 对象列表快照 | 非破坏性标注 | 几百字节/步 |

三种共存不是设计失误——它们的**编辑语义本来就不同**。统一成一种会让每一类都很别扭：像素编辑没有对象、对象编辑不需要像素。
