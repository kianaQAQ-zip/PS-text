## 顺序为什么必须让用户看见

同一组参数，两种顺序跑出来：

| 顺序 | 结果尺寸 | 水印亮区宽度 |
|---|---|---|
| 先缩放 → 后加水印 | 200×150 | **81 px** |
| 先加水印 → 后缩放 | 200×150 | **40 px** |

差了整整一倍。原因是后一种顺序里水印被当作画面的一部分一起重采样，字跟着缩小了。

这是个**产品语义**问题而不是实现细节：把它固定成一条隐式管道，等于替用户做了一个他看不见的决定。
所以步骤列表可增删、可上下移，而且面板上写明「顺序会影响结果」。

## "预览不骗人"是靠什么保证的

预览是在**降采样的小图**上跑同一套步骤的，这里有个必须处理的矛盾：
缩略图里的"长边 1600 px"到底该多大？

解决办法是 `BatchContext.Scale` 把参数分两类：

- **绝对**像素参数（长边、边框粗细、固定字号）→ **必须乘**缩放因子；
- **相对**参数（百分比、宽度百分比）→ **必须不乘**，因为降采样不改变比例关系，乘了反而错。

自检直接断言 `ReadTargetSize`：长边 800 在全分辨率下给 800×600，在半缩放预览下给 400×300；
而百分比模式在两种上下文下给出同一个尺寸。

最终校验打在整条链路上：面板显示「实际输出约 800 × 600 px」，自检把它和**真正写出的文件尺寸**比对，
容差 1%（预览基于整数因子降采样，取整链条必然带 1~2 px 误差）。实测完全一致。

> **预览没有复用 `LoadPreviewAsync`**：那条路径不做 EXIF 方向校正，手机竖拍照片会在预览里躺倒，
> 而实际输出是按校正后的方向来的——预览会骗人。所以改为整幅解码（方向正确）再降采样。

## 水印默认按图像宽度百分比

批量图的尺寸常常不一致。固定像素字号会让 4000 px 的大图上水印小到看不见、600 px 的小图上占满半屏。

自检：同一个 10% 宽度字号，在 1200 px 图上占 19.2%，在 400 px 图上占 19.3%。

相对字号还有个附带好处——它在降采样预览里天然还是对的，不需要额外换算。

## 输出命名防住三种覆盖

| 规则 | 为什么需要 |
|---|---|
| 磁盘上已有同名文件 → 让号 | 常规情况 |
| **同一次运行内已分配的名字 → 让号** | 来自不同文件夹的两个同名文件撞名时，磁盘上还没有第二个文件，`File.Exists` **根本查不出来**，会静默互相覆盖 |
| 目标路径 == 源文件 → 让号 | 后缀被清空时目标名会与原名重合 |

第二条是这次真正的陷阱。自检里专门构造了"磁盘上没有、只在本次运行已分配集合里"的场景来钉住它。

另外两处边界：后缀里的非法字符会被替换（用户手输的，不该靠调用方约束）；
GIF 输入在"沿用原格式"时改写为 PNG 并在状态里写明原因
（GIF 只有 256 色且可能是多帧，把照片写回 GIF 会静默毁掉画质）。

## 顺带修掉：`TextOverlayFilter` 不需要 UI 线程

`TextOverlayFilter` 的注释一直写着"RenderTargetBitmap 必须在 UI 线程创建"。
但这个约束**不成立**——WPF 对这些类型的真实要求是"创建与使用在同一线程"，并没有规定必须是 UI 线程。
证据有两条：自检一直在普通线程直接调 `Apply` 且从未失败；这次更把整条含水印的流水线放到线程池线程上跑通，
并断言线程号不同（1 → 28）、产出的水印可见。

这条修正不是纸面清理：不解除的话，批量每张图都要切回 UI 线程排队，界面会一顿一顿。
顺带把 `ApplyAsync` 从"同步返回已完成任务"改成真的 `Task.Run`，单张加字时 UI 也不再僵住。

## 批量没有撤销（这是刻意的）

批量只写新文件、原文件不动，**天然可重来**——重跑一次即可。
这与单张编辑需要三种撤销模型是两件事，不必强行统一：

| 模型 | 用在哪 |
|---|---|
| 整幅压缩快照 | 滤镜 / 裁剪 / 缩放 / 旋转 |
| 区域历史（包围盒前后像素） | 仿制图章 |
| 对象列表快照 | 非破坏性标注 |
| **（无）** | **批量——因为它不修改任何已有数据** |

## 端到端验证

自检里跑了一次真实批量：`big.png`(1600×1200) + `small.png`(400×300) + 一个坏文件。
流水线是「长边 800（只缩不放）→ 10% 宽度水印」。

- 坏文件失败但不影响其它文件；
- big → 800×600（长边约束生效）；
- small → 400×300（**只缩不放**，没被放大）；
- 再跑一次 → 自动生成 `big_批量_2.png`，原有输出没被覆盖；
- 预览推算 800×600，实际文件 800×600。

## 没做的部分（说清楚，不假装完整）

- **每张图独立参数**：批量 = 一套参数套所有图。要逐张调就先单张编辑——这是刻意的边界，不是缺口。
- **水印平铺**：目前是九宫格单点放置，没有做平铺满画面。
- **EXIF / ICC 完整保留**：走的是 WPF 编码器路径，只保 DPI。放 P2。
- **批量的任意角度旋转**：只支持 90° 倍数（批量场景下任意角度旋转很少见，且会引入画布扩边与填色的一整套参数）。
