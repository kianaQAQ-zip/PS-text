## 遮盖标注：与其它标注的本质区别

其余标注都是**几何 + 颜色**，而遮盖的内容是**底图的像素级派生**。好在叠加层与合并渲染
都只是 `DrawGeometry(Fill, pen, geo)`，所以把 `Fill` 换成一个 `ImageBrush` 就塞进去了 ——
**渲染器一行都没改**。

但有一个必须守住的约束：**叠加层与合并必须共用同一份素材**。如果两边各生成一份，
马赛克的相位、模糊的程度就可能不一致，变成"所见非所得"。所以素材来源做成了
`IMosaicSourceProvider`，两处传同一个实例（与"共用几何"是同一个道理）。

### 三个关键决定

**① 不做"整幅预处理 + 缓存"。** 12MP 图整体像素化是一份 48 MB 的位图，而遮盖标注通常
只有几百像素见方。改成"按标注矩形现场生成"是几十 KB、亚毫秒级，于是可以跟着拖动逐帧重算。
附带的好处更大：**不存在"底图换了忘了失效"这一类缺陷** —— 那是最典型的隐性 bug 来源。

**② 素材是"拉取"而不是"推送"的。** provider 持一个取像素的委托，每次现取现用。
不需要在任何改动底图的地方记得通知它失效。代价只是每次取一次源缓冲的引用，
而那个缓冲在 ViewModel 里本身就有缓存（与调整预览共用）。

**③ 块网格锚定在整幅图的 (0,0)。** 若按区域自己的左上角起算，标注每移动一个像素、
所有块边界就跟着挪，拖动时马赛克会"闪烁流动"。所以区域会先**向外对齐到块边界**再处理，
并把实际起点回传，由调用方按它摆放笔刷。

自检直接钉住这条性质：用相差 2px 的两次请求取同一块区域，
断言**同一图像坐标处的块值完全相同**。

| 断言 | 实测 |
|---|---|
| 纯色图块平均逐像素等于原色（常值解） | ✅ 0 个像素偏色 |
| 每块的值 = 该块在原图上的算术平均 | ✅ 全部吻合 |
| 块内像素完全一致（硬边方块而非糊） | ✅ |
| 同一图像坐标块值与请求起点无关 | ✅ 抽样 15 个块 |
| 贴边区域模糊不越界（外扩生效） | ✅ B=3 落在 0~83 内 |
| **合并后矩形外像素逐字节不变** | ✅ 0 个像素被改动 |

最后一条是遮盖类工具的安全性底线 —— 打码工具要是把矩形外的像素也动了，那就是事故。

## 八向缩放手柄

缩放的逻辑全是"边界与钳制"：不允许翻转、最小尺寸、保持宽高比、以中心为基准，
四者叠在一起分支很多。所以核心计算做成了纯函数（`AnnotationResizeCalculator`），
自检可以逐条钉死：

| 行为 | 说明 |
|---|---|
| 拖右下角 | 左上角一动不动，只改宽高 |
| 拖边中点 | 只改一个方向（纵向不受指针影响） |
| 拖过头 | **钳制在最小尺寸，而不是翻转** —— 翻转会让手柄瞬间跳到对面，对箭头更是灾难 |
| Shift | 保持宽高比（只对四角生效，边中点没有宽高比可言） |
| Alt | 以中心为基准，两边对称变化 |

### 三个交互细节

**手柄命中优先于"拖动标注"。** 否则"抓角缩放"永远被当成"挪位置"，尺寸永远改不了。
自检里专门有一条：抓右下角拖动之后，左上角必须原封不动。

**手柄尺寸按「屏幕像素 ÷ 缩放」折算。** 放大到 800% 时手柄不会变成一坨巨块，
缩到 10% 也还点得中。自检断言 100% 是 11px、200% 是 5.5px。

**文字标注用"与字号成比例的虚拟盒"。** 文字的几何盒是 1×1 的点（文字从锚点往右下画），
直接拿它当手柄框会让八个手柄叠在一起。用虚拟盒之后，"拖角 = 改字号"的手感就对了。

另外：箭头缩放会**保留原始方向**（从右下指向左上的箭头不会掉头）；
光标提示由 ViewModel 出"名字"、XAML 用转换器落地 —— 这样 code-behind 仍然不设置任何控件外观，
符合项目既有的职责边界。

### 顺带修掉一个被自检抓出来的缺陷

`VisualBounds`（视觉包围盒，用于命中测试）原来统一写成 `max(线宽, 字号*0.6) + 4`。
而 `FontSize` 对**所有**标注都有默认值 28 —— 于是一个 4px 粗的矩形也带了 20 多像素的抓取边距：
在它旁边点一下会被判成"选中并拖动"，而不是"在空白处新建标注"。

这个缺陷的发现过程很典型：`[35]` 的端到端用例想在空白处点一下新建文字标注，
结果挪动了箭头，报"文字拖角应变大字号（28 → 28）"。查下去才发现文字压根没被创建。
现在外扩量按类型取：细矩形 6px、文字 20.8px、箭头 16px、遮盖 0。

## 右键菜单

在 `SystemFileAssociations\image\shell` 下挂两个动词：

| 菜单项 | 命令 |
|---|---|
| 用 PS-text 编辑 | `"PS-text.exe" "%1"` |
| 用 PS-text 打印 | `"PS-text.exe" --print "%1"` |

挂在 `image` 这一层而不是逐个扩展名各挂一份：一处就能覆盖所有"感知类型为图片"的文件，
注销时也只有一个地方要清理。用 `MUIVerb` 写显示名（默认值会被资源管理器当成动词名
再去找本地化字符串）；**不写 `Extended`**，所以不必按住 Shift 就能看到。

### 为什么"打印"只到预览为止

Windows 自己的图片"打印"动词也是弹向导的。静默送打印机会造成"怎么突然多出一沓纸"的事故，
而且用户没法取消。所以 `--print` 定义为"打开图片并进入打印预览"，并在接线时明确
**不提供**静默打印选项。

自检额外钉住：注销后动词键与空的 `shell` 键都要清理干净，但**不动**
`SystemFileAssociations\image` 这一层 —— 那是系统结构，别的程序也可能往里挂东西。

## 多文档标签页（架构级改动）

### 改造思路

原来的 `MainViewModel` 把"当前文档"的所有状态平铺成实例字段（`_document`、`_history`、
`_annotations`、`_adjustments`、各种缓冲区缓存、`_zoomFactor`…），一共 **374 处引用**。

逐个改调用点风险太高。实际做法是：**把这些私有字段换成"转发到当前会话"的私有属性**。

```csharp
private ImageDocument _document
{
    get { return _activeSession.Document; }
    set { _activeSession.Document = value; OnDocumentReplaced(); }
}
```

于是 **374 处调用点一行都没改**，而"切换标签 = 换一整套状态"自动成立。
类里所有代码看起来仍然在操作"当前文档"，实际读写的是当前标签的工作台。

验证方式也很直接：改完之后先跑一遍原有的 299 项断言 —— 它们覆盖加载、编辑、撤销重做、
标注、几何变换、打印的完整生命周期。**全绿就说明重构没有破坏任何行为**，
剩下的才是新功能。

### 两条不变量

**① 至少有一个标签。** 关掉最后一个标签时把它**重置为空会话**而不是从集合里移除。
于是 `ActiveSession` 永不为 null，上面那一堆转发属性一律不用判空 ——
这比到处写 null 检查可靠得多。

**② 切换标签必须整体刷新。** 撤销步数、调整滑块、标注列表、缩放比例**全都属于某个文档**，
切过去之后要整体通知一遍。`RefreshAfterSessionChange()` 因此写得很"啰嗦"：
少通知一个的后果是"切过去之后某一处还显示上一个文档的值"，而这种错位很难定位到是哪个属性漏了。

### 自检的核心断言

多文档这一块最吓人的缺陷是"撤销撤回了另一个文档的操作"。所以自检直接打在这上面：

```
在标签 A 上加一个标注       → A: UndoCount=1, AnnotationCount=1
打开另一张图（开标签 B）     → B: UndoCount=0, AnnotationCount=0   ← 状态确实隔离
切回 A                     → A: UndoCount=1, AnnotationCount=1   ← 历史还在
调整参数（亮度 40）在不同标签上的值互不影响
```

以及：初始只有一个空标签、打开图片复用空标签（不会白留一个空白页）、
已有文档时开新标签并激活、同一时刻只有一个标签被标记为当前、
关闭后自动激活相邻标签、关掉最后一个标签会重置为空标签、`ActiveSession` 永不为 null。

### 标签栏为什么单独放一行

标签栏是**独立的整行**（不在中间的某一列里），因此横跨整个窗口宽度，
不会被右侧 296px 的编辑面板挤成一小截。

> **一个自检覆盖率的坑**：标签栏在没有文档时是隐藏的，而**隐藏的元素不会被测量**，
> `DataTemplate` 也就不会被实例化 —— 模板里的绑定错误在 `[23]`（构造主窗口）里根本暴露不出来。
> 所以 `[36]` 专门开两个标签、真实构造一次窗口再布局，才真正走到那段模板。

## 没做的部分（说清楚，不假装完整）

- **静默打印**：不做，理由见上（会造成无法取消的意外打印）。
- **标签拖拽排序 / 拖出成独立窗口**：不做。要做得引入一整套拖拽命中的逻辑，
  而收益很小 —— 文件数不多时标签顺序并不重要。
- **批量水印平铺、每张图独立参数、EXIF/ICC 完整保留**：仍未做。
- **窗口 / 面板状态记忆、i18n**：仍未做。
