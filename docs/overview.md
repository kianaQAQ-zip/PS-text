## 关键实现决策

**未保存确认为什么不在 code-behind 里写业务逻辑。** `Closing` 是同步事件，而"保存"必须异步（编码走线程池）。
因此拆成两半：ViewModel 的 `ConfirmCloseAsync()` 判断"要不要保存、能不能关"（它才知道 `IsDirty` 语义），
窗口只负责"先 `Cancel` 掉这次关闭，问完用户再放行"。用户选"保存"时走的是与 `Ctrl+S` 完全相同的
`SaveAsync`，所以"先提交降采样预览再写盘"这条既有保障不会被绕过；保存失败或用户在另存为对话框里取消，
`IsDirty` 仍为 true → 拒绝关闭，不会丢图。

**崩溃日志为什么要探测可写性。** 只 `CreateDirectory` 不够 —— 受限环境里目录建得出来却写不进去。
`CrashLogger` 会真写一个探针文件再删掉，确认可写才采用，否则退回临时目录。本次实测中
`%LOCALAPPDATA%` 恰好在沙箱里不可写，**回退路径被真实触发并工作正常**，等于顺带验证了降级逻辑。

**图标为什么要两套变体。** 完整版（照片卡片 + 山峰 + 太阳 + 文本条）在 32px 以上清晰，
但 16/24px 下细节会糊成一团；小尺寸改用加粗简化版。渲染在 1024px 上完成再 LANCZOS 降采样，保证边缘干净。

## 过程中的一个环境发现

构建命令（VS2022 MSBuild）被本机工具层的可执行文件黑名单拦截，Bash 与 PowerShell 均无法直接调用；
最终改用 Python `subprocess` 调起完成构建。自检也需要把 `TEMP` 指向项目内可写目录才能运行。
这两点已记入项目备忘，后续构建可直接复用。
